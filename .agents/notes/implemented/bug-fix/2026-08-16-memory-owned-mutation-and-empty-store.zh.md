# Agent Note：Memory 自有变更与干净安装空库

Status: implemented

[English](2026-08-16-memory-owned-mutation-and-empty-store.md) | 中文

## 问题

最初的 [Memory 插件决策](../feature/2026-08-14-memory-plugin.md)正确选择 Markdown 作为跨会话事实源，却把写入委托给通用文件系统工具。ClawDSH profile 把 Memory 放在 `DSH_HOME` 下的私有全局根目录，而交互 Session 只拥有工作区范围的文件系统权限。用户在会话 A 中说明长期身份时，模型没有获授权的操作去创建缺失的 Memory 根目录或写入文件；会话 B 随后对不存在的目录调用 `memory_search` 与 `memory_get`，因而无法召回身份。单元测试 fixture 预先创建了根目录，所以没有覆盖干净安装失败。

原设计也缺少精确更正或遗忘操作。追加改变后的事实会保留矛盾，而允许模型自由选择路径又会把写权限扩大到两个 Memory 自有目标之外。

## 决策

Memory 自有四个工具。`memory_search` 与 `memory_get` 保持既有读取约定。`memory_write` 只接受固定的 `durable` 或 `daily` scope，只写 `MEMORY.md` 或当天的 `memory/YYYY-MM-DD.md`，不接受路径。`memory_update` 在模型读取文件后，替换或移除 `MEMORY.md` 中的一条精确行。完全相同的长期事实会去重，日常记录保持追加语义。

缺失的配置根目录是合法空库。搜索不调用 Embeddings 并返回无匹配，读取说明尚无存储记忆，第一次成功的自有写入创建根目录和固定目标。系统提示要求模型主动保存稳定身份、偏好、关系、决策和长期项目，避免秘密与临时事实，并在语义搜索不可用时直接用 `memory_get` 读取。

变更通过文件系统接缝执行，使用能力自有的 `workspace-write` 权限且仅限配置的 Memory 根目录。操作拒绝符号链接根目录、日记目录和目标文件。进程内按目标串行化，并用文件系统 revision compare-and-swap 保留并发宿主修改；观察过期时基于最新内容重试。返回模型的错误只保留稳定文件系统错误码，绝不泄露物理根路径。

watcher 把启动时缺失的根目录视为可恢复状态。第一次写入后，它关闭祖先监听并在新根目录上重开；dispose 会等待恢复和 watcher 关闭完全收敛。

## 考虑过的替代方案

**继续用通用文件系统工具写入。** 否决：Session 工作区策略正确拒绝全局个人记忆根目录。把每个 Session 的工作区扩大到 `DSH_HOME` 会让无关工具获得更宽的私有状态权限。

**安装时创建目录并保留通用写入。** 否决：这只隐藏第一次失败。文件系统权限仍然错误，安装迁移或用户清理都可能重新产生缺失根目录状态。

**让 `memory_write` 接受模型选择的相对路径。** 否决：日常与长期记忆只需要两个派生目标；路径参数会引入能力并不需要的遍历、命名空间和保留策略。

**从语义排序静默降级为词法排序。** 既有 Memory 决策已经否决，因为这会改变评分语义。直接 `memory_get` 是读取长期文件的显式、可记录降级方式。

## 影响

默认 profile 现在可以从空安装建立长期 Memory，并在后续 Session 中召回。写入、更正和遗忘都是模型可见的工具调用与结果，因此可从 Session 日志重建。Activity 只投影隐私安全结果，不包含事实正文或物理路径。

Memory 现在拥有一个窄范围变更面及其并发生命周期。宿主编辑仍然权威，但若宿主持续制造 revision 冲突，模型变更会等待到成功或被取消；操作不会因固定重试次数耗尽而覆盖较新版本。

Ark Embeddings 对产品启动仍然可选。未配置或不可用时，语义搜索响亮失败，而模型仍可直接读取长期文件。不会从凭据存在推断远端就绪。

## 验证

聚焦测试覆盖缺失根目录、跨调用写入与召回、精确去重、日记追加、更正与遗忘结果、并发宿主变更、符号链接拒绝、脱敏错误、watcher 恢复、dispose 竞态和固定提示指引。最终产品验收还会在正常 ClawDSH profile 中创建 Memory，并从另一条 Web Session 召回。
