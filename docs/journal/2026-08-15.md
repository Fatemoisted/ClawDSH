## Telegram credentialed end-to-end verification

### Credential handling and composition

- The run used a dedicated Telegram bot through the `TELEGRAM_BOT_TOKEN` credential reference and a Harness model through `DEEPSEEK_API_KEY`. No token or chat id is recorded in this journal or the repository.
- A repository-external profile overlay enabled Telegram and disabled Feishu/Discord for isolation. The shipped profile remains opt-in for Telegram and names `botTokenEnv: TELEGRAM_BOT_TOKEN`; its Ark embedding row names `apiKeyEnv: ARK_API_KEY`.
- A direct Bot API `getMe` probe established authentication before the daemon run. The config dump remained a composition check, not authentication evidence.

### Passed paths

- Private chat: `/start`, an exact unique-marker reply, and native reply-to-source delivery.
- Durable memory: a fact was written, the daemon stopped cleanly, and the same fact was recalled after restart with the same `DSH_HOME`.
- Group routing: an unmentioned message was gated; a username mention and a reply to the bot were admitted.
- Command routing: `/help@BotUsername` preserved `/help`; a command addressed to another bot was isolated.
- Harness tool execution: a current-information prompt completed through `web_search` and returned to Telegram.
- Message normalization: an addressed media caption reached the model, while bodyless media was ignored.
- Transport and recovery: offline catch-up, Unicode-safe splitting above 4096 UTF-16 units, interrupted-turn recovery, and same-chat FIFO all completed.

### Memory and recovery evidence

`ARK_API_KEY` was intentionally absent. `memory_search` failed loud with its missing-credential error, after which the agent used the narrower `memory_get` fallback to read the stored fact. A clean restart preserved the durable session; a separately interrupted turn recovered on the next launch; a message sent while offline was collected after polling resumed; and two rapidly admitted messages in one chat completed in FIFO order.

### Negative gates

- An ordinary group message without an address produced neither acknowledgement nor model reply when Telegram was configured to deliver it to the test bot.
- A command addressed to a different bot did not count as a mention of this bot.
- Media with neither text nor caption did not create a model turn.

### Coverage boundary

- A real Telegram forum topic was not exercised. Topic propagation and isolation remain keyless contract coverage until a real-client row passes.
- Acknowledgement reactions have keyless contract coverage but were not independently observed during this credentialed run.
- Managed-credential hot rotation, missing-credential capability shutdown, permanent polling-stop behavior, and chat-id migration aliases were not counted as live passes in this run. Keyless coverage verifies that 401 disables receive/send/react, while 409 disables receive only.
- At the time of this live run, the adapter relayed media captions and ignored bodyless media; it did not download image bytes. This paragraph records that observed build and must not be read as proof of the later attachment implementation.
- Long polling remains process-local for FIFO, without a durable provider inbox/outbox or transactional multi-chunk delivery.

### Post-baseline keyless implementation

After the live run, the current implementation added ephemeral photo/image-document sources and an adapter materialization hook. Keyless tests cover PNG/JPEG/WebP/GIF document mapping, largest-photo selection, group admission and model-modality checks before materialization, provider-declared oversize rejection before download, official `@grammyjs/files` hydration of `getUrl`, and native `fetch` streaming under an abortable deadline before Harness `ctx.attachments` import. They also cover durable image references for image-capable models, caption continuation with omitted-image context on text-only models, and the fixed image-only notice without a model turn. The implementation caps actual bytes, validates every selected input before saving any reference, and exposes `imageDownloadTimeoutMs` with a 30000 ms default and a 1000–2147483647 range. These are not credentialed real-client passes; the shipped DeepSeek selection is text-only and therefore does not download Telegram image bytes.

The current migration implementation also has keyless coverage for preconfigured alias routing, an in-memory pause after an unaliased migration service update, and invalid alias rejection. The pause is only best effort: Telegram may deliver ordinary new-id traffic before that service update, and restart/remount loses the pause set. Only an alias configured before new-id traffic guarantees reuse of the old durable session identity.

### Result

The credentialed baseline closes Telegram private/group text routing through the real Bot API, Harness agent/model/tools, durable session and Memory layers, and outbound delivery. The exact repeatable procedure, failure signals, and non-baseline rows are in the [Telegram end-to-end cookbook](../cookbook/telegram-e2e.md); package-level behavior and limits remain in the [Telegram adapter README](../../packages/openclaw/channel-telegram/README.md).
