## Evidence scope after the channel-plane replacement

This journal preserves credentialed evidence from the in-process adapter implementation that is now mounted under `ctx.legacyChannels`. ADR-0008 subsequently made the locked OpenClaw Gateway sidecar the canonical communication plane. The historical runs below do not certify that sidecar: they used different host code, provider ownership, admission logic, identity mapping, persistence ledgers, media handling, and delivery paths.

## Telegram credentialed end-to-end verification

### Credential handling and composition

- The run used a dedicated Telegram bot through the `TELEGRAM_BOT_TOKEN` credential reference and a Harness model through `DEEPSEEK_API_KEY`.
- A repository-external profile overlay enabled Telegram and disabled Feishu/Discord for isolation. The rebuilt profile now exposes the equivalent compatibility path through the default-disabled `clawdsh-legacy-channel-plane` group and a separate Telegram entry switch.
- A direct Bot API `getMe` probe established authentication before the daemon run. The config dump remained a composition check, not authentication evidence.

### Passed paths

- Private chat: `/start`, an exact unique-marker reply, and native reply-to-source delivery.
- Durable Memory: a fact was written, the daemon stopped cleanly, and the same fact was recalled after restart with the same `DSH_HOME`.
- Group routing: an unmentioned message was gated; a username mention and a reply to the bot were admitted.
- Command routing: `/help@BotUsername` preserved `/help`; a command addressed to another bot was isolated.
- Harness tool execution: a current-information prompt completed through `web_search` and returned to Telegram.
- Message normalization: an addressed media caption reached the model, while bodyless media was ignored.
- Transport and recovery: offline catch-up, Unicode-safe splitting above 4096 UTF-16 units, interrupted-turn recovery, and same-chat FIFO all completed.

### Memory and recovery evidence

`ARK_API_KEY` was intentionally absent. `memory_search` failed loud with its missing-credential error, after which the Agent used the narrower `memory_get` fallback to read the stored fact. A clean restart preserved the durable Session; a separately interrupted turn recovered on the next launch; a message sent while offline was collected after polling resumed; and two rapidly admitted messages in one chat completed in FIFO order.

### Negative gates

- An ordinary group message without an address produced neither acknowledgement nor model reply when Telegram was configured to deliver it to the test bot.
- A command addressed to a different bot did not count as a mention of this bot.
- Media with neither text nor caption did not create a model turn on the tested pre-image-ingestion build.

### Coverage boundary

- A real Telegram forum topic was not exercised. Topic propagation and isolation remain keyless coverage until a new real-client row passes.
- Acknowledgement reactions have keyless coverage but were not independently observed during this credentialed run.
- Managed-credential hot rotation, missing-credential capability shutdown, permanent polling-stop behavior, and chat-id migration aliases were not counted as live passes. Keyless coverage verifies that 401 disables receive/send/react, while 409 disables receive only.
- At the time of this live run, the adapter relayed media captions and ignored bodyless media; it did not download image bytes. This observed behavior is not proof of the later attachment implementation.
- Long polling remains process-local for FIFO, without a durable provider inbox/outbox or transactional multi-chunk delivery.

### Post-baseline keyless implementation

After the live run, the legacy implementation added ephemeral photo/image-document sources and an adapter materialization hook. Keyless tests cover PNG/JPEG/WebP/GIF mapping, largest-photo selection, group admission and model-modality checks before materialization, declared/actual size bounds, official `@grammyjs/files` URL hydration, abortable native streaming, and Harness attachment import. They also cover durable image references for image-capable models, caption continuation with omitted-image context on text-only models, and the fixed image-only notice without a model turn. These are not credentialed real-client passes.

The legacy migration implementation also has keyless coverage for preconfigured alias routing, an in-memory pause after an unaliased migration service update, and invalid alias rejection. The pause is only best effort: ordinary new-id traffic may arrive first, and restart/remount loses the pause. Only an alias configured before new-id traffic guarantees reuse of the old durable Session identity. ADR-0011 owns this compatibility behavior; it does not specify sidecar behavior.

### Result

The credentialed baseline closes legacy Telegram private/group text routing through the real Bot API, Harness Agent/model/tools, durable Session and Memory layers, and outbound delivery. The exact repeatable procedure, failure signals, and non-baseline rows are in the [Telegram legacy E2E cookbook](../cookbook/telegram-e2e.md). The current sidecar remains default-disabled, uncertified, and governed separately by ADR-0008 and the channel sync standard.
