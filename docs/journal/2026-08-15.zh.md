本日志保留目前挂载在 `ctx.legacyChannels` 下的进程内 adapter 实现的带凭证证据。ADR-0008 后来把锁定的 OpenClaw Gateway sidecar 确立为 canonical 通信平面。以下历史运行不能认证该 sidecar：两者使用不同的 host code、provider ownership、准入逻辑、identity mapping、持久 ledger、媒体处理与投递路径。

| 旧 adapter | 带凭证证据 | 重要边界 |
|---|---|---|
| 飞书 | 2026-08-14 文本消息 → 官方 Lark WebSocket ingress → Harness Agent → `im.message.create`；用户确认收到 | 后续 Harness 凭据引用/热切换修订只有无密钥测试；没有当前 sidecar live smoke |

## Telegram 带凭证端到端验证

### 凭据处理与组装

- 本轮通过 `TELEGRAM_BOT_TOKEN` 凭据引用使用专用 Telegram bot，并通过 `DEEPSEEK_API_KEY` 使用 Harness 模型。
- 仓库外 profile overlay 启用 Telegram，并禁用飞书/Discord 以隔离测试。重建后的 profile 通过默认关闭的 `clawdsh-legacy-channel-plane` group 与单独 Telegram entry switch 暴露等价 compatibility path。
- daemon 测试前用 Bot API `getMe` 直接探针确认身份。配置 dump 仍只是组装检查，不是鉴权证据。

### 已通过路径

- 私聊：`/start`、精确唯一 marker 回复，以及原生 reply-to-source 投递。
- 持久 Memory：写入一项事实，干净停止 daemon，再以同一 `DSH_HOME` 重启后召回同一事实。
- 群聊路由：未 mention 消息被门控；用户名 mention 与 reply-to-bot 被准入。
- Command 路由：`/help@BotUsername` 保留 `/help`；指向其他 bot 的 command 被隔离。
- Harness tool 执行：时效性问题经 `web_search` 完成并回传 Telegram。
- 消息规范化：带定向文本的媒体 caption 达到模型，无正文媒体被忽略。
- 传输与恢复：离线补收、超过 4096 UTF-16 unit 的 Unicode-safe 分片、中断回合恢复与同一 chat FIFO 均完成。

### Memory 与恢复证据

本轮刻意不提供 `ARK_API_KEY`。`memory_search` 以缺凭据错误明确失败，随后 Agent 使用更窄的 `memory_get` 回退读取已存事实。干净重启保留了持久 Session；另一次被中断的回合在下一次启动时恢复；离线期间发送的消息在 polling 恢复后补收；同一 chat 快速准入的两条消息按 FIFO 顺序完成。

### 负向门控

- 在 Telegram 已配置为把普通群消息投递给测试 bot 的前提下，未定向普通群消息既不产生 ack，也不产生模型回复。
- 指向不同 bot 的 command 不算对当前 bot 的 mention。
- 在受测的 pre-image-ingestion build 上，既无文本也无 caption 的媒体不会创建模型回合。

### 覆盖边界

- 尚未在真实 Telegram forum topic 中测试。Topic 传递与隔离仍只有无密钥覆盖，直至新的真实客户端行通过。
- Ack reaction 有无密钥覆盖，但本轮带凭证测试未独立观察。
- 托管凭据热切换、缺凭据时关闭 capability、永久停止 polling 的 behavior 与 chat-id migration alias 均不计为本轮线上通过。无密钥覆盖验证 401 会关闭 receive/send/react，而 409 只关闭 receive。
- 本次线上测试时 adapter 会转发媒体 caption，并忽略无正文媒体；它不会下载图片字节。该实际观察不能证明后续 attachment 实现已通过线上验证。
- 长轮询的 FIFO 仍只在进程内成立，且没有持久 provider inbox/outbox 或事务式多分片投递。

### 基线之后的无密钥实现

线上测试之后，legacy 实现新增了短暂 photo/image-document source 与 adapter materialization hook。无密钥测试覆盖 PNG/JPEG/WebP/GIF mapping、最大 photo 选择、先通过群聊准入与模型模态检查再 materialize、声明/实际大小限制、官方 `@grammyjs/files` URL hydration、可取消 native streaming 与 Harness attachment import。测试还覆盖图片模型使用持久引用、文本模型 caption 携带 omitted-image context 继续，以及纯图片固定提示且不创建模型回合。这些都不是带凭证真实客户端通过项。

旧 migration 实现还通过无密钥测试覆盖预配置 alias 路由、无 alias migration service update 后的内存暂停，以及无效 alias 拒绝。该暂停仅为 best effort：普通新 id 流量可能先到达，restart/remount 也会丢失暂停。只有在新 id 流量前配置 alias，才能保证复用旧持久 Session identity。ADR-0011 拥有该 compatibility behavior；它不规定 sidecar behavior。

### 结果

带凭证基线已闭环 legacy Telegram 在真实 Bot API 上的私聊/群聊文本路由、Harness Agent/模型/tool、持久 Session 与 Memory 层，以及出站投递。准确可复现流程、失败信号与非基线行见 [Telegram legacy E2E 手册](../cookbook/telegram-e2e.md)。当前 sidecar 仍默认关闭、未经认证，并由 ADR-0008 与渠道同步规范单独治理。
