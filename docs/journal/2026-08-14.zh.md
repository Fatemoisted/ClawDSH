## 排查记录：首次 typecheck 失败与修复

- **现象**：`pnpm run typecheck` 在 tsdown host 阶段报 `[clawdsh] Cannot find entry: lib/types/{index,invariant,startup}.js`。
- **根因**：tsdown 的 workspace 扫描以**目录**为粒度（`onlyDirectories: true`），`packages/openclaw/*` 骨架目录被扫中；目录内无 package.json → 向上寻根到根包（name=`clawdsh`）→ 用根配置解析入口失败。此前"骨架不放 package.json"策略只防住了 pnpm，未防住 tsdown。
- **修复**：根 `tsdown.config.ts` 的 workspace 改为对象形式并显式 `exclude: ['packages/openclaw/**']`（exclude 会整体替换 tsdown 内置默认值，四条默认模式已原样保留）。该改动已写入 ADR-0001 决策 4 的"构建编排最小豁免"。

## 阶段 2 收尾：渠道适配器 SDK 化重构（发起人方向，2026-08-14）

- **Cordis 契约不变**：两者仍是函数插件（named-export `name`/`inject`/`Config`/`apply`）+ `ChannelAdapter` 契约 + `ctx.effect(() => ctx.channels.registerAdapter(...))` 注册；`start()` 返回 disposer（飞书 `wsClient.close({force:true})`、Telegram `bot.stop()`）。测试注入 seam（`AdapterDeps.client`/`AdapterDeps.bot`）保持协议映射可测。
