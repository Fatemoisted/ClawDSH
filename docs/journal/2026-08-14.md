## Debugging note: first typecheck failure and fix

- **Symptom**: `pnpm run typecheck` reported `[clawdsh] Cannot find entry: lib/types/{index,invariant,startup}.js` at the tsdown host stage.
- **Root cause**: tsdown's workspace scan is directory-granular (`onlyDirectories: true`), so the `packages/openclaw/*` skeleton directories were swept in; no package.json inside the directory → root resolution walked up to the root package (name=`clawdsh`) → resolving the entry with the root config failed. The earlier "no package.json in the skeleton" strategy only blocked pnpm, not tsdown.
- **Fix**: the root `tsdown.config.ts` workspace was changed to object form with an explicit `exclude: ['packages/openclaw/**']` (exclude wholesale-replaces tsdown's built-in defaults; the four default patterns were kept verbatim). This change was recorded in ADR-0001 decision 4's "build-orchestration minimal exemption".

## Phase 2 wrap-up: channel-adapter SDK-ification refactor (sponsor direction, 2026-08-14)

- **Background**: the first channel-feishu hand-rolled a `node:http` webhook + bare `fetch` to the im OpenAPI, and channel-telegram hand-rolled getUpdates polling. The sponsor corrected course: it should "first look at how OpenClaw itself implements it, then at how to plug into the Cordis modular design", to avoid hand-rolling errors (Feishu has permissions/long-connection and other ceremony).
- **Feishu SDK-ification**: switched to the official `@larksuiteoapi/node-sdk` (`^1.73.0`) — `Lark.EventDispatcher` registers `im.message.receive_v1` + `Lark.WSClient` long-connection inbound (SDK auth + ACK, idempotent dedup by `message_id`); `Lark.Client.im.message.create` outbound (the tenant token lives with the SDK `tokenManager`). **Long connection replaces the webhook**: removed the four configs `port`/`path`/`encryptKey`/`verificationToken`, added `domain` (feishu/lark).
- **Telegram SDK-ification**: switched to `grammy` (`^1.45.1`) — `Bot.on('message:text')` + `bot.start({allowed_updates:['message'], timeout})` long-poll inbound; `bot.api.sendMessage` outbound; the offset belongs to the grammY long-poll loop, and the adapter no longer holds state.
- **Cordis contract unchanged**: both are still function plugins (named-export `name`/`inject`/`Config`/`apply`) + the `ChannelAdapter` contract + `ctx.effect(() => ctx.channels.registerAdapter(...))` registration; `start()` returns the disposer (Feishu `wsClient.close({force:true})`, Telegram `bot.stop()`). Tests inject the seam (`AdapterDeps.client`/`AdapterDeps.bot`) to keep the protocol mapping testable.
- **Principle recorded**: `docs/standards/plugin-contract.md` gained "§8 OpenClaw feature porting principle — look at the implementation first, then integrate into Cordis" (read the upstream origin first → then choose the seam/form → prefer reusing the upstream's proven SDK, never hand-roll the low-level protocol).
- **Verification**: feishu contract tests 9/9, telegram 7/7, full `pnpm typecheck` green, `gen-config-catalog` regenerated.

### Deliverable B: Memory plugin + embeddings seam (commit `d79397e98b` + `335d3247f1`)

- **Storage choice overturns the handoff preset**: `SpillStore` only has saveText, is session-isolated, and its locator is opaque with no read API — mutually exclusive with "cross-session, readable back, human-editable". Switched to a **`ctx.fs` Markdown-file source of truth** (`MEMORY.md` + `memory/YYYY-MM-DD.md`, aligned with OpenClaw's original design), with zero plugin writes (the model writes via the fs tools; the observation policy's version guard catches idempotency).
- **New seam `ctx.embeddings` (ADR-0003)**: dsh has no embedding facility anywhere (`ctx.llm` has no embed endpoint), and semantic recall is the only real gap. A three-package split: `embeddings` (Service Definition, single implementation — mixing providers breaks cosine comparability) + `embeddings-ark` (Volcano Ark `doubao-embedding-vision-251215`, multimodal endpoint sends text only; credentials resolved per-operation in layers from `ARK_API_KEY`; response validation includes cross-call dimension-drift fail-loud) + `memory` (Consumer). **Upstream proposal deferred** (following the ADR-0002 precedent, ADR-0003 records the divergence rationale).
- **memory form**: `inject=['tools','systemPrompt','fs']`; `memory_search`/`memory_get` recall on demand (no per-request auto-injection — isomorphic to OpenClaw); the `clawdsh:memory-recall` section has order 115; the index is in-memory derived data, rebuilt incrementally by `(version,size)`, one embed batch per search; fail-loud when no provider; **no new session event needed** (the section goes into `request/header`, recalls go into tool results).
- **Credentials**: the ARK API Key goes into the root `.env` (gitignored, not committed); the preset's `embeddings-ark` row **starts disabled** (no key does not affect boot).
- **Build chain**: three packages × tsconfig paths/references + tsdown removed memory from its exclusion line (the ADR-0001 exemption area); preset profile patch `insert` of memory (`root: !!js dshHomePath('memory')`) + embeddings-ark two rows.
- **Pitfalls**: ① a non-global regex (no `/g`) `exec` loops forever → OOM (PARAGRAPH_SPLIT got `/g`); ② this repo's transform pipeline downgrades a sparse array's `for...of entries()` to hole-reads (undefined) overriding `fill(0)` — both the stub and the hot path use explicit index loops + guards; ③ under vitest `tsconfig paths` only maps the package root, so deep-path imports in tests use relative paths; ④ lint forbids non-null assertions (`!`), use an explicit guard or `?? 0`; ⑤ the lefthook pre-commit blocks a commit that fails lint.
- **Verification**: three packages' contract tests 26/26 (keyless), full typecheck green, `pnpm run build` green, `verify-package-invariants` (226 companions all pass, soul tsconfig back to green after adding an invariants reference), `verify-cordis-config` (122 files pass), `--dump-config` smoke (a temporary DSH_HOME resolved memory + embeddings-ark(disabled) for the new profile with a memory row). Real ARK e2e is deferred to phase 3 (README Known Limitations already records that the wire shape is unmeasured).
